SR LINUX v24.10.1 — AGENT CHEAT SHEET (read-only commands)
Nokia 7220 IXR / 7250 IXR / 7730 SXR

================================================================================
TWO ROUTES TO DEVICE DATA  (pick deliberately)
================================================================================
  get_state_path(device, "<yang-path>")    # operational state
  get_config_path(device, "<yang-path>")   # running config

  - Accepts native YANG path notation, INCLUDING `[name=<value>]` list keys
    and slash-joined containers. No CLI parser quirks apply.
  - Returns structured JSON for any leaf or container.
  - If the path you need isn't in KEY STATE PATHS below, call
    search_yang_paths(keyword, domain) first, then GET the returned path.

CLI command:
  execute_show_command(device, "<cli-command>")

  - Use for formatted operational views (`show interface brief`,
    `show network-instance default route-table`, `show version`) or for
    actions (`ping`, `traceroute`).
  - The CLI parser is much fussier than `get` — see CLI PATH SYNTAX below
    if you must traverse a YANG path through the CLI.

================================================================================
DATASTORES  (CLI vocabulary, only relevant inside execute_show_command)
================================================================================
show <x>                  formatted operational view
info /path                raw running config at YANG path
info from state /path     raw operational state at YANG path
info detail /path         running config including all defaults

CLI PATH SYNTAX  (only applies when used through execute_show_command —
                  prefer get_state_path / get_config_path which accept YANG paths as-is)
  - Segments are SPACE-SEPARATED in CLI, not joined by '/'.
  - List keys are SPACE-SEPARATED VALUES, NEVER [name=VALUE] bracket form.
    Quoting the bracket form ([name="..."]) also fails.
  - `info detail /<list>` without a key errors "Missing value for 'name'" —
    always supply the key.

  YANG path                                       CLI form
  /system/information                          -> info from state system information
  /interface[name=ethernet-1/1]                -> info from state /interface ethernet-1/1
  /interface[name=ethernet-1/1]/oper-state     -> info from state /interface ethernet-1/1 oper-state
  /interface[name=ethernet-1/1]/statistics     -> info from state /interface ethernet-1/1 statistics
  /network-instance[name=default]              -> info detail /network-instance default
  /network-instance[name=default]/protocols/bgp -> info from state /network-instance default protocols bgp

OUTPUT MODIFIERS (append to any CLI command)
  | as json    | as yaml    | grep <pat>    | head <N>    | no-more

WILDCARDS (24.3+):  ethernet-1/{1..5}   ethernet-1/*   [name=*]
