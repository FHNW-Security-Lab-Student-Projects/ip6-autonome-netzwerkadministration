# Nokia SR Linux CLI Knowledge Base

## CRITICAL: SR Linux vs Other Network OS

Nokia SR Linux uses a UNIQUE CLI syntax that is DIFFERENT from:
- Cisco IOS/IOS-XE (NO "interface GigabitEthernet", NO "ip address" commands)
- Juniper JunOS (different config hierarchy)
- Arista EOS (different command structure)

ALWAYS use SR Linux native syntax as documented below.

## CLI Architecture

SR Linux uses a hierarchical configuration model with these key concepts:

1. **Path-based configuration**: All config uses paths like `/interface/ethernet-1/1`
2. **Subinterfaces**: Physical interfaces have subinterfaces (e.g., `ethernet-1/1.0`)
3. **Network instances**: Layer 3 routing contexts (similar to VRFs)
4. **JSON-like structure**: Config follows a tree hierarchy

## Command Modes

### Show Commands (Read-only)
- Execute in any mode
- Always start with `show`
- No configuration changes

### Configuration Commands
- Use `enter candidate` to enter config mode
- Make changes with `set` or direct path navigation
- Use `commit now` to apply changes
- Use `discard` to abandon changes

## Configuration Syntax

### General Pattern
```
set /<path>/<to>/<resource> <parameter> <value>
```

### Interface Configuration

#### Enable Physical Interface
```
set / interface ethernet-1/1 admin-state enable
```

#### Create Subinterface with IPv4
```
set / interface ethernet-1/1 subinterface 0
set / interface ethernet-1/1 subinterface 0 ipv4 admin-state enable
set / interface ethernet-1/1 subinterface 0 ipv4 address 192.168.1.1/24
```

#### Create Subinterface with IPv6
```
set / interface ethernet-1/1 subinterface 0 ipv6 admin-state enable
set / interface ethernet-1/1 subinterface 0 ipv6 address 2001:db8::1/64
```

#### Configure Interface Description
```
set / interface ethernet-1/1 description "Link to Router2"
```

#### Configure MTU
```
set / interface ethernet-1/1 mtu 9000
```

### System Interface (Loopback)
```
set / interface system0 admin-state enable
set / interface system0 subinterface 0
set / interface system0 subinterface 0 ipv4 admin-state enable
set / interface system0 subinterface 0 ipv4 address 10.0.0.1/32
```

### Network Instance Configuration

#### Associate Interface with Network Instance
```
set / network-instance default interface ethernet-1/1.0
set / network-instance default interface system0.0
```

#### Configure Router ID
```
set / network-instance default router-id 10.0.0.1
```

#### Create Custom Network Instance (VRF)
```
set / network-instance vrf-blue type ip-vrf
set / network-instance vrf-blue admin-state enable
set / network-instance vrf-blue interface ethernet-1/2.0
set / network-instance vrf-blue router-id 10.0.0.1
```

### Static Routes
```
set / network-instance default static-routes route 0.0.0.0/0 next-hop-group group1
set / network-instance default static-routes route 0.0.0.0/0 admin-state enable
set / network-instance default next-hop-groups group group1 nexthop 1 ip-address 192.168.1.254
```

### BGP Configuration
```
set / network-instance default protocols bgp admin-state enable
set / network-instance default protocols bgp autonomous-system 65001
set / network-instance default protocols bgp router-id 10.0.0.1

# BGP Neighbor
set / network-instance default protocols bgp neighbor 192.168.1.2 peer-as 65002
set / network-instance default protocols bgp neighbor 192.168.1.2 admin-state enable
```

### ACLs and Filters
```
set / acl ipv4-filter filter1 entry 10 match ipv4 source-ip prefix 192.168.1.0/24
set / acl ipv4-filter filter1 entry 10 action accept
```

## Common Mistakes to Avoid

### WRONG (Cisco IOS syntax)
```
interface GigabitEthernet0/0
 ip address 192.168.1.1 255.255.255.0
 no shutdown
```

### CORRECT (SR Linux syntax)
```
set / interface ethernet-1/1 admin-state enable
set / interface ethernet-1/1 subinterface 0
set / interface ethernet-1/1 subinterface 0 ipv4 admin-state enable
set / interface ethernet-1/1 subinterface 0 ipv4 address 192.168.1.1/24
set / network-instance default interface ethernet-1/1.0
```

### WRONG (Generic show commands)
```
show ip interface brief
show run
show running-config
```

### CORRECT (SR Linux show commands)
```
show interface brief
show running-config
info from running
```

## Interface Naming

- Physical interfaces: `ethernet-1/1`, `ethernet-1/2`, etc.
- Subinterfaces: `ethernet-1/1.0`, `ethernet-1/1.1`, etc.
- System interface (loopback): `system0.0`
- Management interface: `mgmt0`

## Network Instance Types

1. **default**: Default routing instance (always exists)
2. **ip-vrf**: Layer 3 VRF
3. **mac-vrf**: Layer 2 EVPN instance

## Best Practices

1. **Always enable interfaces**: Interfaces and subinterfaces need `admin-state enable`
2. **Subinterface association**: Use `interface <name>.<subinterface-id>` when associating with network-instance
3. **Order matters**: Create interface/subinterface before associating with network-instance
4. **Use candidate mode**: Always use `enter candidate` for configuration changes
5. **Verify before commit**: Use `diff` to see changes before `commit now`
6. **IPv4/IPv6**: Explicitly enable protocol admin-state for each address family

## Validation Commands

Before committing configuration, verify:
```
# Check candidate configuration

# Compare with running config

# Validate specific interface

# Check network instance config

```

## Important Notes

1. SR Linux is MODEL-DRIVEN: All config follows YANG models
2. Interface subinterfaces must be created before configuration
3. Network instance associations use subinterface notation (e.g., `ethernet-1/1.0`)
4. Many features require explicit `admin-state enable`
5. Configuration is hierarchical - understand the path structure
